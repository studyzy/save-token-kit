# SKILL: stk

Token 优化流水线的唯一编排入口。启动时从 `save-token/` 产物推导当前进度，输出流水线状态图，从断点续跑。四个阶段的**完整执行逻辑分别位于同级的 4 个 skill**（`../stk-diagnose/SKILL.md`、`../stk-analyze/SKILL.md`、`../stk-optimize/SKILL.md`、`../stk-report/SKILL.md`），本文件只做编排调度，**不复制其内容**——按需读取对应 SKILL.md 并按其执行。

## 核心原则

**单入口 ≠ 自动驾驶。** 每个阶段结束都设停点，默认值只降低操作成本；**无用户显式确认，不落地任何修改**。

## 执行流程

### 步骤 1: 状态推导

检查 `./save-token/` 下产物，按下表确定当前阶段（产物是唯一依据，不猜测）：

| 产物状态                                                  | 当前阶段           |
| --------------------------------------------------------- | ------------------ |
| `diagnosis-report.md` 缺失，或「扫描时间」距当前 > 5 分钟 | 1 诊断（**重跑**） |
| 诊断新鲜 + `tasks.md` 缺失                                | 2 分析             |
| `tasks.md` 存在且有未勾选项（`- [ ]`）                    | 3 优化             |
| `tasks.md` 全部勾选 + `save-token-report.json` 缺失       | 4 报告             |
| `save-token-report.json` 已生成                           | 完结               |

**诊断过期的处理**：诊断报告 > 5 分钟视为过期。此时**不要静默重跑**，先向用户说明「检测到诊断基线已过期（生成于 <扫描时间>），将重新诊断」并给出继续/取消的选择；用户取消则停止。

> 说明：多处并发会话可能覆盖同一份 `diagnosis-report.json`（同一 `./save-token/` 目录）。报告阶段对比基线前，先核对 `diagnosis-report.json` 的 `scanTimestamp` 与 `tasks.md` 的生成时间——若报告比 tasks.md 更新，说明基线已被后续诊断覆盖，须提示用户「基线已变化，前后对比可能失真」。

**失败任务的处理**：`stk-optimize` 对失败任务保持 `- [ ]` 并追加 `⚠️ 失败：<原因>`（**不勾选**）。推导"优化阶段"时，若存在带 `⚠️ 失败：` 标注的未勾选项：

- 状态图标注 `优化 ●（有 N 项失败）`，N 为失败标注条数；
- 询问用户是「重试失败项」还是「跳过失败项并进入报告」；
- 选「进入报告」后照常推进，但 report 阶段报告中须**单列失败清单**（任务 ID + 原因），不得因失败项未勾选而卡在优化阶段无法前进。

### 步骤 2: 输出流水线状态图

执行任何动作前，先输出一行状态图与断点说明：

```
Token 优化流水线：诊断 ✓ → 分析 ✓ → 优化 ● 进行中 → 报告 ○
检测到 tasks.md 有 6 条未完成，从「优化」阶段继续。
```

### 步骤 3: 意图直达（可选）

用户调用时附带明确意图（如「只要报告」「重新诊断」）→ 直接路由到对应阶段，不做全链推进（阶段内停点规则不变）。所路由阶段的前置产物缺失时，提示缺失项并询问是否先补齐，不臆造数据。无明确意图 → 询问「从『阶段 N』继续？」（默认推荐 = 状态推导结果；用户可 Other 指定其他阶段）。

### 步骤 4: 阶段执行与链式衔接

读取并按对应阶段的 SKILL.md 执行：

| 阶段   | 读取                       | 衔接                                                         |
| ------ | -------------------------- | ------------------------------------------------------------ |
| 1 诊断 | `../stk-diagnose/SKILL.md` | 报告展示后 AskUserQuestion「继续分析？」（默认继续）         |
| 2 分析 | `../stk-analyze/SKILL.md`  | tasks.md 产出后进入「优化」阶段的任务级选择                  |
| 3 优化 | `../stk-optimize/SKILL.md` | 摘要输出后 AskUserQuestion「生成前后对比报告？」（默认继续） |
| 4 报告 | `../stk-report/SKILL.md`   | AskUserQuestion「开新一轮（重新诊断）/ 结束」（默认结束）    |

任一停点用户选「停在这里」→ 立即停止，不执行后续阶段；下次 `/stk` 从断点续跑。

> 路径回退：若相对路径不可达，尝试 `<skills 根目录>/stk-<stage>/SKILL.md`；仍找不到则提示用户重跑 `stk init`，停止。

## 边界

- 状态误判的后果仅为重复某阶段（幂等：诊断覆盖写、优化跳过已勾选项），可接受。
- 本 SKILL 只编排不执行；各阶段细节一律以对应 SKILL.md 为准。
- 4 个阶段 skill 仍可被用户单独调用（行为 = 流水线单步），单独调用时不触发链式衔接。
