# /stk 单一入口设计（4 SKILL 整合）

日期：2026-09-24
状态：设计已确认，待实施

## 背景与问题

当前 `stk init` 安装 4 个平级 SKILL：`/stk-diagnose` → `/stk-analyze` → `/stk-optimize` → `/stk-report`，构成严格串行的流水线。UX 问题：

1. **认知负担**：4 个入口，用户必须自己记住顺序。
2. **错误驱动导航**：靠"前置产物缺失才提示先跑上一步"引导（如 optimize 缺 `tasks.md` 时才指向 analyze）。
3. **多次手动触发**：完整旅程需 4 次命令 + 多轮问答。
4. **状态不可见**：进度只能靠查看 `save-token/` 产物文件推断。

## 目标形态（已确认）

- **单一主入口 `/stk`**：自动检测产物状态、断点续跑、阶段链式衔接。
- **旧 4 个 SKILL 保留为高级入口**：供精确控制单步重跑；description 加"高级·单步"前缀引导新用户。

## 架构：薄分发器 + 共享阶段文档

不合并 4 个 SKILL 内容（会是 40K+ 巨型文件），而是 ~2K 状态机分发器 + 单一事实源的阶段文档：

```
src/templates/skills/
├── stk/                    ← 新主入口
│   ├── SKILL.md            ← ~2K：状态检测 + 断点续跑 + 路由 + 确认点矩阵
│   └── stages/             ← 各阶段执行细节（单一事实源）
│       ├── diagnose.md
│       ├── analyze.md
│       ├── optimize.md
│       └── report.md
├── stk-diagnose/SKILL.md   ← 瘦身为 ~0.5K，指向 stages/diagnose.md
├── stk-analyze/SKILL.md    ← 同上
├── stk-optimize/SKILL.md   ← 同上
└── stk-report/SKILL.md     ← 同上
```

按需读取对应 `stages/*.md` 执行；改逻辑只改一处。

## 状态机：产物 → 阶段映射

流水线状态完全由 `save-token/` 产物推导，无需新增 CLI 命令：

| 产物状态 | 当前阶段 |
|---|---|
| `diagnosis-report.md` 缺失 / 过期（>5 分钟，沿用 analyze 现有阈值） | 1 诊断 |
| 诊断新鲜 + `tasks.md` 缺失 | 2 分析 |
| `tasks.md` 有未勾选项 | 3 优化 |
| 全部勾选 + `save-token-report.json` 缺失 | 4 报告 |
| 报告已生成 | 完结 → 询问开新一轮或结束 |

## 交互设计：每阶段设停点，默认值驱动

单入口 ≠ 自动驾驶。**无显式确认不落地任何修改**，默认值只降低操作成本。

### 确认点矩阵

| 停点 | 询问 | 默认值 |
|---|---|---|
| `/stk` 入口 | 从「阶段 N」继续？ | 推荐阶段（可 Other 指定其他阶段） |
| 诊断完成 | 继续分析？ | 是 |
| 场景收集 | analyze 第一轮 3 必问合并为一次 AskUserQuestion | —（必答） |
| tasks.md 产出 | **执行哪些任务？**（见下） | 仅推荐，不自动执行 |
| 优化完成 | 生成前后对比报告？ | 是 |
| 报告完成 | 开新一轮 / 结束 | 结束 |

### 入口状态图

`/stk` 执行任何动作前先输出一行流水线位置：

```
Token 优化流水线：诊断 ✓ → 分析 ✓ → 优化 ● 进行中 → 报告 ○
检测到 tasks.md 有 6 条未完成，从「优化」阶段继续。
```

### 优化阶段的任务级选择（关键变更，替代原"按等级单选"）

tasks.md 产出后在对话中展示完整清单（编号 + 等级 + 动作 + 预估节省），**必须** AskUserQuestion 询问：

- 全部（推荐）
- 仅初级
- 初级 + 中级
- 用户可在 Other 直接输入编号清单（如 `1.1, 2.3, 3.1`）

选定集合内顺序执行、逐条回写 `tasks.md`（沿用现有 optimize 逻辑），执行中不逐条打断。

### 断点续跑边界规则

- 诊断报告 >5 分钟 → 视为过期，重跑诊断。
- `tasks.md` 全部勾选 → 直接问"是否生成对比报告"。
- 报告已生成 → 输出上次节省摘要，问"开新一轮（重新诊断）还是结束"。
- `/stk` 后附带意图（如 `/stk 只要报告`）→ 路由到对应阶段，不做全链推进。

## 配套微优化

- 旧 4 个 SKILL `description` 统一加"高级·单步"前缀。
- WorkBuddy / tool-opt 等平台分支规则保留在 stage 文档内，不受重组影响。
- 一次完整旅程交互：1 次 `/stk` + 每阶段 1 次确认（含任务选择），替代原 4 次手动命令。

## 改动落点

- `src/templates/skills/`：新增 `stk/`（SKILL.md + stages/），旧 4 个 SKILL.md 瘦身。
- `stk init` / `stk install --agent` 安装清单加入新 skill。
- CLI 代码基本不动（状态检测复用现有产物约定）。

## 非目标

- 不改 `stk diagnose` CLI 数据采集逻辑。
- 不动 analyze 的 12 个子 Agent 体系与状态机（PENDING→SUCCESS 等）。
- 不引入新的持久化状态文件（产物即状态）。
